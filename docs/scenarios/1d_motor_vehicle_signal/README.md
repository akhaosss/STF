# 1.d 机动车信号灯场景

> 文档关系：首次部署先阅读仓库根目录 [README](../../../README.md) 和 [环境安装与验证](../../environment_setup.md)；本文只说明当前1.d专项流程。

本分支实现 GB/T 41798—2022 6.1.4 所需的普通圆形机动车信号灯测试流程：

- 初始绿灯；
- 转红工况在车身最前端距停止线 40～60 m 时触发（默认目标为 50 m）；
- 黄灯 3 s、红灯 30 s，然后恢复绿灯；
- 直行、左转、右转各执行同一路线 3 次；
- 每组三次同时覆盖保持绿灯和转红工况；
- 乘用车红灯直行/左转检查不越线、停车距离不超过 2 m、绿灯后 3 s 内起步；
- 普通圆形红灯右转检查车辆不停车并在红灯期间通过停止线。

## 1. 绘制路线并生成测试矩阵

先启动并加载目标 CARLA 地图，然后运行：

```bash
python waypoints.py \
  --name TOWN10HD_Opt \
  --scenario 1d \
  --maneuver straight \
  --seed 41798 \
  --save_dir ./save_scenarios/1d
```

编辑器中的颜色含义：

- 橙色路点和箭头：地图中受交通信号灯控制的车道路段；
- 紫色 Ego 路线：当前绘制路线经过信号控制区域；
- 红色圆点：交通信号灯 Actor；
- 绿色 Ego 路线：尚未匹配到交通信号灯。

操作顺序：

1. `Ctrl + 左键` 放置 Ego，起点应位于停止线前 60 m 以上；
2. `Shift + 左键` 在目标信号灯或其停止线附近放置信号灯提示点；
3. `Alt + 右键` 依次绘制路线，路线应穿过停止线并延伸至路口后的目标车道；
4. 按 `J`、`K`、`L` 分别选择左转、直行、右转；
5. 按 `S` 为当前路线生成 3 个可复现测试配置。

直行、左转、右转各绘制并保存一次，即得到最低 9 次测试。保存目录中的
`1d_matrix_manifest.json` 记录每个文件的基础种子、派生矩阵种子、逐次试验种子、路线指纹、工况和配置哈希。

同一路线的三次工况采用受约束随机生成：序列可随机变化，但一定同时包含
`keep_green` 和 `turn_red`。相同 `--seed`、地图、路线几何和转向类型会生成相同矩阵。

## 2. 运行

`run.py` 不会根据 `--town` 自动切换地图。开始测试前必须确认 CARLA 当前地图与
`--town` 完全一致；1.d 分支会在不一致时直接拒绝运行。

使用内置参考控制器验证场景设施：

```bash
python run.py \
  --input_dir ./save_scenarios/1d \
  --town TOWN10HD_Opt \
  --scenario 1d \
  --model behavior \
  --video_dir ./videos
```

正式运行默认检查直行、左转、右转矩阵都存在，且每条路线恰好有 3 次并覆盖两种灯色工况。
若只想调试一条已经完整生成的三次矩阵，可追加 `--allow_partial_matrix`。

评测 TCP 模型：

```bash
python run.py \
  --input_dir ./save_scenarios/1d \
  --town TOWN10HD_Opt \
  --scenario 1d \
  --model tcp \
  --model_path /path/to/best_model.ckpt \
  --video_dir ./videos
```

`behavior` 是场景自检用参考控制器；正式算法结论应使用实际被测模型。

## 3. 结果文件

每完成一次试验都会立即更新：

```text
videos/1d/
├── 1d_result.md       # 单一、可阅读和归档的完整报告
├── 1d_result.json     # 完整结构化结果及仿真元数据
├── 1d_result.csv      # 表格分析/导入电子表格
├── 1d_result.pkl      # Python原始快照
└── scenario_*.mp4     # 每次试验视频
```

报告记录：路线类型、工况、种子、配置哈希、触发距离、实际黄/红灯时长、停车距离、
绿灯起步延迟、红灯越线、异常停车、最高速度、碰撞、路线完成状态、最终判定和失败原因。
元数据还包含 CARLA 客户端/服务端版本以及 TCP 权重文件的 SHA-256（使用 TCP 时）。
运行器启动时会读取既有 JSON 账本，并以新的 `run_id` 追加本轮结果，因此中途退出后续跑或
多次重复试验不会覆盖之前的结果。

## 4. 可复现条件

重放试验时需保持以下项目一致：

- CARLA及Python API版本；
- 地图和地图资源；
- 被测模型及权重；
- `1d_matrix_manifest.json` 中列出的输入 JSON；
- 同步步长（当前为 0.05 s）；
- 基础种子、派生矩阵种子和逐次试验种子。

配置文件中不保存 CARLA Actor ID，因为重载地图后 Actor ID 会变化；信号灯按其触发位置
重新匹配，输入配置哈希则用于确认试验定义没有发生变化。
